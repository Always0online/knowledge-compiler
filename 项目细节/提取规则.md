# 提取规则：L1/L2/L3 与收录边界

> 本文定义「提取什么、什么值得进知识库」，是提取 LLM 的提示词与判定依据。

## 分类定义

- L1 洞察：项目特定的坑、bug 根因、修复方法与具体经验，relevance 3-4。
- L2 框架：可迁移的方法论、流程、原则、架构，relevance 4-5。
- L3 决策规则：IF 症状/场景 THEN 解法/动作，relevance 3-5。
- relevance 1-2：一次性信息，默认丢弃，不进入知识库。

## 收录边界与价值筛选

优先收录（高价值）：

- 项目或环境特有的坑：配置、依赖、平台兼容、权限等。
- 已解决 bug 的根因与修复方式，尤其是可能复发的。
- 跨会话可复用的操作经验、命令、流程。
- 决策依据与「为什么这么做」。

不收录（低价值）：

- 互联网一搜就有、且与项目无关的通用知识。
- 纯聊天、寒暄、一次性任务记录。
- 官方文档能稳定查到的内容。

收录判断：下次遇到类似情况，这条能否让自己少踩坑或少查一次。能则收，不能则丢。

## 输出 JSON schema

```json
{
  "items": [
    {
      "level": "L1 | L2 | L3",
      "title": "string",
      "content": "string",
      "relevance": 3,
      "source_quote": "string（可选，尽量原话）",
      "domain": "string（不确定填 null）",
      "if": "string（仅 L3）",
      "then": "string（仅 L3）",
      "why": "string（仅 L3）",
      "related": ["string"]
    }
  ]
}
```

## few-shot 示例

- L1 洞察：`{"level":"L1","title":"Windows 上 apply_patch 空行需带 + 前缀","content":"add_file 的空行如果不带 + 前缀会报 invalid hunk header。","relevance":3,"domain":"codex"}`
- L2 框架：`{"level":"L2","title":"确定性触发优先于模型自觉","content":"捕获和编译必须由事件触发，不写进 prompt 让模型自觉执行。","relevance":5,"domain":"agent-memory"}`
- L3 决策规则：`{"level":"L3","title":"rollout 文件静默后再处理","if":"rollout 文件 LastWriteTime 超过 5 分钟未变","then":"判定为完整，进入提取队列","why":"会话期间文件持续追加，过早读取会残缺","relevance":4,"domain":"detection"}`
