# 系统规格：自动记忆编译流水线

> 依据：`骨架/knowledge-compiler-replacement-plan.md` 与 `提取规则.md`

## 解析适配器契约

### 输入

rollout JSONL，每行 `{ timestamp, type, payload }`。

### 保留规则

- 保留 `response_item.payload.type` 为 `message` 的行：取 `role` + `content`。
- 保留 `reasoning`：默认丢弃，节省 token；需要时可开。
- 保留 `function_call` / `custom_tool_call`：取工具名 + 参数摘要。
- `function_call_output` / `custom_tool_call_output`：若含错误或失败信息（stderr、非零 exit code、error、exception、traceback 等），优先保留完整；正常输出才截断到前 500 字符。
- 丢弃 `session_meta`、`world_state`、`turn_context`、`event_msg`。

### raw markdown 模板

```markdown
# Session <timestamp>

## 对话
- user: ...
- assistant: ...

## 工具调用
- <tool_name>: <参数摘要>

## 工具结果
- <tool_name>: <前 500 字符，错误信息完整保留>
```

### token 截断

单次送入提取 LLM 的 raw 总预算默认 30000 token。超过时优先保留最近事件与错误信息，向前丢弃最早内容。

## 状态表 schema

状态文件：`<KC 项目根目录>/.state/state.jsonl`，每行一条记录。

```json
{
  "rollout_path": "string",
  "sha256": "string",
  "last_event_id": "string | null",
  "processed_at": "ISO8601 | null",
  "status": "pending | processing | done | error",
  "error": "string | null"
}
```

规则：

- 只处理 `status` 为 `pending` 的记录。
- 写入用临时文件 + 重命名，保证原子性。
- 崩溃恢复：启动时把超过 30 分钟的 `processing` 重置为 `pending`。

## 领域路由规则

- 提取 LLM 返回 `domain` 字段。
- `domain` 非空：写入 `knowledge_library/domains/<domain>/<insights|frameworks|decision-rules>/`。
- `domain` 为空或未知：写入 `_inbox`，人工审核后再归类。

## LLM 接口配置

默认决策：OpenAI 兼容云模型，首推 DeepSeek。

```env
EXTRACT_LLM_BASE_URL=https://api.deepseek.com/v1
EXTRACT_LLM_API_KEY=sk-...
EXTRACT_LLM_MODEL=deepseek-chat
EXTRACT_LLM_MAX_TOKENS=4096
EXTRACT_LLM_TIMEOUT_MS=120000
EXTRACT_LLM_RETRIES=3
```

本地模型备选：Ollama + Qwen，`EXTRACT_LLM_BASE_URL=http://127.0.0.1:11434/v1`。

## 已定决策

- 完成信号：默认静默时间 5 分钟；Stop Hook 完成标记作为后续可选增强。
- 入库方式：默认先入 `_inbox` 人工审核；验证稳定后改为直写。

## 技术栈

默认决策：Node.js + TypeScript，单一运行时。

- JSONL 解析：逐行 `JSON.parse`。
- 文件监听：`chokidar`，用 `awaitWriteFinish` 做静默判断。
- LLM 调用：`fetch`。
- Markdown 写入：`node:fs`。

## 运行与调度（部署方式）

默认决策：不做常驻进程，用 Windows 任务计划程序定时跑 `scan`，每 5-10 分钟一次。

- 不采用「开机自启常驻」：流水线只在 Codex 产生 rollout 时有活，常驻浪费且需要 babysit。
- 不采用「伴随 Codex 启动」：Codex 没有干净的伴生进程钩子，包装脚本脆弱。
- 首选：任务计划程序 + `scan`，每轮处理完即退出，重启后任务仍在。
- 近实时备选：`watch` 常驻，注册为「登录时启动」。

包装脚本：`scripts/scan.bat`、`scripts/watch.bat`。

注册命令：

```powershell
schtasks /create /tn "KC-extract" /sc minute /mo 10 /tr "<KC 项目根目录>\scripts\scan.bat"
```

## 验收标准

测试夹具：任意一份 rollout 文件，例如项目内 `fixtures/sample-rollout.jsonl`。

验收点：

1. 解析器正确抽取 `message` 与 `function_call`，生成合法 raw markdown。
2. 同一文件处理两次，第二次不产生新条目（游标去重生效）。
3. 提取 LLM 返回符合 schema 的 JSON，L1/L2/L3 各至少一例。
4. 领域路由与 index 更新正确。

## 非阻塞项

- 隐私：云模型外发前，对 raw 中疑似密钥、token、密码的片段做脱敏。
- 日志与重试：JSONL 日志记录每次运行；LLM 失败指数退避重试。
- 版本控制：对 `KC` 目录初始化 git，保留方案与状态历史。
